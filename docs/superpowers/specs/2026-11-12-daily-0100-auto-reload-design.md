# 每日 01:00 自動全部重載設計

## 目標

在「12宮格直播監控 V2.0」執行期間，每天依 Windows 系統本機時間於凌晨 01:00 自動執行一次面板既有的「全部重載」。如果程式在 01:00 沒有執行，當天不補跑，等待隔天 01:00。

## 行為規格

- 排程依 `QDateTime.currentDateTime()` 所讀取的系統本機時間運作。
- 每秒檢查一次時間；當小時為 `1`、分鐘為 `0`，且當天尚未執行時觸發。
- 01:00 這一分鐘內至多執行一次，不因每秒檢查而重複。
- 程式若在 01:01 或更晚才啟動，不補執行當天排程。
- 跨日後清除「當天已執行」限制，隔天 01:00 可再次執行。
- 自動排程直接呼叫 `ChromeEmbedWindow.reload_enabled_slots()`，與使用者按面板「全部重載」共用相同程式路徑，不模擬滑鼠點擊。
- 自動執行後，狀態列顯示「每日 01:00 已自動全部重載」。
- 手動「全部重載」不算作當日自動排程，仍保留 01:00 的自動執行。

## 架構

新增一個不依賴 UI 的小型排程判斷元件，負責接收目前時間並判斷是否應觸發。它只保存最近一次自動執行的日期，不寫入設定檔或磁碟。

`ChromeEmbedWindow` 建立一個 `QTimer`，每秒把目前系統時間交給排程元件；元件回傳應觸發時，視窗呼叫既有 `reload_enabled_slots()`，再更新狀態列。視窗關閉時停止計時器。

## 錯誤與邊界

- 排程不另行吞掉 `reload_enabled_slots()` 的錯誤；沿用現有重載流程與各格狀態顯示。
- 系統時間在 01:00 內向前或向後調整時，以日期鎖避免同一天重複執行。
- 系統從睡眠恢復時若已超過 01:00，不補跑；若仍在 01:00 這一分鐘內且尚未執行，則執行一次。
- 不新增 Windows 工作排程器、背景服務或外部程序。

## 測試

排程判斷元件以固定時間測試：

- 00:59 不觸發。
- 01:00 觸發。
- 同一天 01:00 再次檢查不重複觸發。
- 01:01 不補跑。
- 隔天 01:00 再次觸發。

視窗整合測試確認自動觸發共用 `reload_enabled_slots()`，並更新指定狀態文字。最後執行完整單元測試與 V2.0 建置流程。
